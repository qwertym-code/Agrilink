# Deploying Agrilink

The API and the site deploy separately:

| Part | Host | Directory |
| --- | --- | --- |
| Express API | Render | `server/` |
| React client | Vercel | `client/` |

Because they end up on different origins, the API's CORS list has to name the
site's URL explicitly — that is the one wiring step people usually miss.

---

## Before you deploy — do these first

**1. Rotate the database password.**
The connection string used in development was shared over chat, so treat it as
compromised. Atlas → *Database Access* → your user → *Edit Password* →
*Autogenerate*. Update `server/.env` locally with the new one too.

**2. Open Atlas to the API host.**
Atlas → *Network Access*. Render's outbound addresses are not fixed on the free
plan, so the practical setting is `0.0.0.0/0` (allow from anywhere). That is
only acceptable because access still requires the database password — which is
exactly why step 1 comes first.

**3. Never commit `.env`.**
It is git-ignored. `server/.env.example` documents the variables without values.

---

## Step 1 — Push to GitHub

Both hosts deploy from the repository.

```bash
git push -u origin main
```

`demo.txt` contains a home IP address. It is deliberately left uncommitted —
do not `git add` it.

---

## Step 2 — API on Render

1. [render.com](https://render.com) → sign up → **New → Blueprint**.
2. Connect the `Agrilink` repository. Render reads `render.yaml` and proposes
   a service named **agrilink-api**.
3. It will ask for the two values marked `sync: false`:
   - `MONGO_URI` — your **new** Atlas connection string, with `/agrilink`
     before the `?`.
   - `CLIENT_URL` — leave as `http://localhost:5173` for now; you don't have a
     Vercel URL yet. You'll come back to this in step 4.
4. Deploy. When it finishes, open `https://<your-service>.onrender.com/api/health`
   — it should return `{"status":"ok"}`.

`JWT_SECRET` is generated by Render automatically. You never see it and you
don't need to.

> **Free tier sleeps after 15 minutes idle.** The first request afterwards takes
> roughly 30 seconds while the service wakes. Not a bug — mention it if you're
> demoing this to someone.

---

## Step 3 — Client on Vercel

1. [vercel.com](https://vercel.com) → sign up → **Add New → Project** → import
   the same repository.
2. **Set Root Directory to `client`.** This is the critical setting; Vercel
   defaults to the repo root and the build will fail without it.
   Framework preset, build command and output directory come from
   `client/vercel.json`.
3. Add one environment variable:

   | Name | Value |
   | --- | --- |
   | `VITE_API_URL` | `https://<your-service>.onrender.com/api` |

   Note the `/api` suffix — the client appends paths like `/products` to it.
   Vite inlines `VITE_*` variables at build time, so changing this later
   requires a redeploy, not just a restart.
4. Deploy. You get a URL like `https://agrilink-xyz.vercel.app`.

---

## Step 4 — Point the API back at the site

Render → **agrilink-api** → *Environment* → set:

```
CLIENT_URL = https://agrilink-xyz.vercel.app
```

Save. Render restarts automatically.

Until this is done, every request from the site fails with a CORS error in the
browser console while the API itself looks perfectly healthy — a confusing
symptom worth recognising.

To let Vercel's per-commit preview deployments reach the API as well, set
`ALLOW_VERCEL_PREVIEWS=true`. Leave it off unless you need it; it widens the
allow-list to any `*.vercel.app` subdomain.

---

## Step 5 — Seed produce (optional)

To put the demo farm and its 12 listings in the production database, run
locally with `server/.env` pointing at the same cluster:

```bash
npm run seed --prefix server
```

Demo retailer: `greenacres@agrilink.demo` / `demo1234`.
**Change or delete that account before showing this to anyone real** — the
password is published in this file.

## Checklist

- [ ] Atlas password rotated
- [ ] Atlas network access allows the API host
- [ ] Pushed to GitHub, `demo.txt` still uncommitted
- [ ] Render deployed, `/api/health` returns ok
- [ ] Vercel deployed with Root Directory `client` and `VITE_API_URL` set
- [ ] `CLIENT_URL` on Render points at the Vercel URL
- [ ] Registering a new account works end to end on the live site
